# discord-hyperhdr-bridge

Трей-приложение на Go: следит за состоянием пользователя в Discord
(мут, глушение, речь, вход/выход из голосового канала) и меняет цвет подсветки
через JSON-API HyperHDR. Управление — иконка в трее + локальная веб-панель.

Статус: **работает end-to-end**. Discord → состояние → правило → цвет на ленте,
трей и веб-панель на месте. Проверено на живой связке Discord + HyperHDR.

## Структура

```

cmd/rpcprobe/main.go          диагностика Discord без HyperHDR: печатает состояния
cmd/gsiprobe/main.go          диагностика CS2: печатает и пишет поток GSI в файл
internal/config/              config.yaml: загрузка, значения по умолчанию, валидация
internal/discord/
  protocol.go                 кадры IPC, опкоды, константы команд и событий
  transport_windows.go        named pipe \\.\pipe\discord-ipc-N (go-winio)
  transport_unix.go           unix-сокет discord-ipc-N
  client.go                   handshake, READY, nonce-RPC, подписки, реконнект
  oauth.go                    AUTHORIZE → token, refresh, кэш token.json
  events.go                   типы полезной нагрузки событий
internal/state/               потокобезопасный Snapshot + подписки
internal/rules/               Snapshot → действие HyperHDR, приоритет + debounce
internal/hyperhdr/            TCP JSON-клиент (19444): color / effect / clear
internal/web/                 HTTP-панель на 127.0.0.1, SSE-поток состояния

                              из assets/icon.png + цветная точка состояния
internal/cs2/

  platform_windows.go         реестр Steam, «игра запущена» без OpenProcess
```

## Правила по умолчанию

Первое совпавшее состояние выигрывает (`rules.order`):

| Состояние | Что делает подсветка |
|---|---|
| `deafened` — звук выключен | красный `255,0,0`: мигнуть 1 раз и гореть, пока состояние активно |
| `muted` — микрофон выключен (self или server) | оранжевый `255,140,0`: мигнуть 1 раз и гореть, пока состояние активно |
| `connected` — просто в канале | `clear` — HyperHDR работает как обычно (захват экрана) |
| `idle` — не в канале | `clear` (вернуть обычный источник) |

Подсветку мост занимает только на время мута/глушения. Мигание настраивается
на любом правиле `type: color`:

```yaml
muted:
  type: color
  color: [255, 140, 0]
  blink_count: 1      # 0 = не мигать, сразу зажечь
  blink_on_ms: 220    # длительность вспышки
  blink_off_ms: 180   # пауза, в неё видно обычный захват экрана
  # hold: false       # только мигнуть и сразу вернуть подсветку HyperHDR
```

В паузах между вспышками и после `clear` приоритет снимается, поэтому сквозь
анимацию видно обычную работу HyperHDR. Смена состояния посреди мигания
прерывает анимацию: новое правило применяется сразу.

Речь (`speaking`) сознательно не используется: Discord шлёт `SPEAKING_START/STOP`
на каждой паузе в фразе, и подсветка от этого мигает. Состояние по-прежнему
читается и видно в `/api/state`, но правила на него не навешаны.

Мост занимает один приоритет HyperHDR (`hyperhdr.priority: 50`) и снимает его
при выходе — обычный захват экрана продолжает работать под ним.

## Что нужно сделать, чтобы это поехало

1. Go 1.23+ (проверено на 1.27) и `go mod tidy` — зависимости подтянутся сами.
2. Заполнить `config.yaml`: `client_secret` из Developer Portal → OAuth2
   (подробности и остальные шаги — `docs/discord-integration.md`).
3. Проверить, что Discord виден:
   ```
   go run ./cmd/rpcprobe -config config.yaml
   ```
   При первом запуске в клиенте Discord появится окно согласия.
4. В HyperHDR: Settings → General → **JSON server** включён, порт 19444;
   если включена авторизация — создать токен и вписать в `hyperhdr.token`.
5. Сборка:
   ```
   .\build.ps1                                # релиз: без консоли, в bin\
   go build -o bin/bridge.exe ./cmd/bridge    # с консолью (для отладки)
   ```
   `build.ps1` собирает с `-ldflags "-H=windowsgui -s -w"`: окна консоли нет,
   приложение живёт в трее. Логи в этом режиме идут в `bin\bridge.log` — пункт
   трея «Открыть лог»; путь переопределяется флагом `-log`, файл начинается
   заново, когда перевалит за 1 МБ.
   Отладочный запуск без трея: `bin\bridge.exe -no-tray -config config.yaml`
   Флаг `-silent` запрещает открывать веб-панель при старте (его ставит автозапуск).

## Автозапуск при входе в Windows

Переключатель есть в двух местах: в веб-панели (раздел «Настройки») и в меню трея
(«Запускать при входе в систему»). Оба пишут одно и то же значение
`DiscordHyperHDRBridge` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` — права
администратора не нужны, автозапуск действует только для текущего пользователя.

В реестр попадает полный путь к exe, абсолютный путь к конфигу и `-silent`
(`"...\bin\bridge.exe" -config "...\bin\config.yaml" -silent`), потому что автозапуск
стартует с произвольным рабочим каталогом. `-silent` гасит `web.open_on_start`: при
входе в систему программа молча садится в трей, а при ручном запуске панель по-прежнему
открывается. Устаревшую строку запуска (например, от версии без `-silent`) мост
переписывает сам при старте — но только если она ведёт на этот же exe. Если exe
переехал, панель отметит запись как чужую и предложит переключить тумблер
туда-обратно, чтобы обновить путь.

Относительные пути из конфига (`discord.token_file`) считаются от каталога самого
конфига, а не от рабочего каталога процесса: иначе при автозапуске `token.json` уходил
бы в `C:\Windows\System32`, где его не записать, и Discord просил бы согласие на
авторизацию при каждом запуске. Сам `config.yaml`, если его нет в рабочем каталоге,
ищется рядом с exe.

API: `GET /api/autostart` — состояние, `POST /api/autostart {"enabled":true}` —
переключить. То же состояние приходит полем `autostart` в `GET /api/status`.

## События подсветки

Все события — и игровые, и Discord — видны в панели в разделе «События»:
название, что делает подсветка, цвет, отметка «сейчас» и переключатель.

| Событие | Подсветка |
|---|---|
| `cs2_dead` — вас убили | красный, два мигания, лента сразу возвращается HyperHDR |
| `cs2_flashed` — ослепило | белый, пока действует вспышка. **Выключено по умолчанию** |
| `cs2_bomb_exploded` — взрыв | ровный цвет 2 с, без мигания |
| `cs2_bomb` — бомба заложена | оранжевый пульс, период 1 с |
| `cs2_bomb_hurry` — меньше 20 с | тот же цвет, период 0,5 с |
| `cs2_bomb_panic` — меньше 5 с | тот же цвет, период 0,18 с |
| `deafened` — звук выключен | красный, мигнуть и гореть |
| `muted` — микрофон выключен | оранжевый, мигнуть и гореть |
| `connected` — в голосовом канале | `clear`, лента у HyperHDR |

Выключенное событие **не гасит ленту**, а уступает ход следующему по приоритету
(порядок задаёт `rules.order`). События CS2 стоят выше состояний Discord: пока
идёт матч, важнее игра, а мут виден в паузах. Выключатель хранится как
`enabled: false` в правиле, поэтому приоритет не теряется между включениями.

Флешка выключена, потому что в записанной сессии её поймать не удалось:
`flashed` везде был `0`, и порог срабатывания остаётся непроверенным. К тому же
белый экран HyperHDR и так отдаёт через обычный захват.

## Интеграция с CS2 (Game State Integration)

Статус: **работает**. Слушатель, установщик конфига, плитка в панели и детектор
событий готовы. Детектор написан и протестирован по реальной записи потока
(`internal/cs2/testdata/session-casual.jsonl`).

Две особенности, выясненные записью, а не документацией:

- **Таймер бомбы игре не отдаётся.** Блоки `bomb` и `phase_countdowns` не
  приходят ни разу — это привилегия наблюдателя. Мост ведёт отсчёт сам от
  появления `round.bomb = "planted"`, длительность в `cs2.bomb_fuse_s`.
- **Игра шлёт кадр только при изменении состояния.** Пока бомба тихо тикает,
  кадров нет, поэтому фазы ускорения двигает собственный тикер моста.
- **О взрыве игра не сообщает.** Ключ `round.bomb` исчезает одинаково и при
  взрыве, и при разминировании. Различаем по своим часам: досидела до конца
  фитиля — взорвалась, исчезла раньше — разминировали.

При отладке поддельными кадрами помните, что запущенная игра шлёт свои: сидя
в меню, CS2 каждые 10 секунд отправляет heartbeat без блока `player.state`,
мост считает это выходом из матча и обнуляет игровое состояние. Для опытов
с инжектором игру лучше закрыть.

CS2 шлёт состояние сама: в каталог `game/csgo/cfg` кладётся файл
`gamestate_integration_hyperhdr.cfg` с адресом, и игра POST-ит туда JSON. Память
не читается, процесс игры не трогается вообще — на этом же механизме работают
стрим-оверлеи, и повода для реакции VAC нет. Дизайн и обоснования:
`docs/superpowers/specs/2026-09-06-cs2-gsi-design.md`.

Установка: панель → «Интеграции» → плитка **CS2** → «Установить конфиг».
Мост найдёт Steam через реестр и `libraryfolders.vdf`. **После установки CS2
нужно перезапустить** — cfg читается только при старте игры.

### Снять дамп потока GSI

Состав полей GSI в CS2 достоверно не документирован, поэтому детектор написан по
реальной записи, а не по догадкам. Повторная запись нужна, если поведение
разъедется после патча игры — или чтобы наконец поймать флешку.

**`gsiprobe` и `bridge` слушают один и тот же порт** — перед снятием дампа мост
надо закрыть через трей, иначе слушатель не поднимется. И указывайте тот же
конфиг, что читает мост: токен пишется в конфиг, и из соседней копии игра
достучаться не сможет.

```
bin\gsiprobe.exe -config bin\config.yaml -install   # затем перезапустить CS2
bin\gsiprobe.exe -config bin\config.yaml -out gsi-dump.jsonl
```

Если конфиг уже установлен из панели, шаг `-install` не нужен.

Дальше — оффлайн-игра с ботами: умереть, поймать флешку, заложить бомбу и дать ей
взорваться. `gsiprobe` печатает каждый кадр, а по Ctrl+C выводит сводку: какие
блоки игра реально прислала и приходил ли `bomb.countdown` (главный открытый
вопрос — в CS:GO этот блок доставался только наблюдателю).

Дамп содержит ваш steamid: перед коммитом в `testdata` его стоит заменить.

## Что уже сделано в слое Discord

- named pipe / unix-сокет, перебор `discord-ipc-0..9`, реконнект с backoff;
- HANDSHAKE → ожидание `READY` → OAuth2 (`AUTHORIZE` + обмен на токен, refresh,
  кэш `token.json`, перевыпуск при отказе) → `AUTHENTICATE`;
- подписки на `VOICE_SETTINGS_UPDATE`, `VOICE_CHANNEL_SELECT`,
  `VOICE_CONNECTION_STATUS`, а также `SPEAKING_START/STOP` и `VOICE_STATE_UPDATE`
  с переподпиской при смене канала;
- начальный снимок (`GET_VOICE_SETTINGS`, `GET_SELECTED_VOICE_CHANNEL`) — состояние
  известно сразу при старте, а не после первого события;
- фильтрация чужих событий по своему `user_id`, ответы на `PING`.
